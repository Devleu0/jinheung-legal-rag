# 진흥 · 법률 근거 찾기 — 쉬운 사용자 안내서

> 이 프로그램은 **법률 자료를 찾아 함께 읽도록 돕는 도구**입니다. 변호사처럼 사건을 판단하거나 법적 책임을 확정하는 서비스가 아닙니다. 실제 데이터와 외부 서비스 연결 검증은 아직 남아 있으며, 시연 자료는 실제 법률이 아닙니다.

처음 사용하는 분은 1~5절, 설치·시연을 준비하는 팀원은 6~8절을 읽으세요.

## 1. 어떤 프로그램인가요?

일상적인 말로 법률 관련 질문을 입력하면, 운영자가 미리 준비한 법령·판례 자료 중 관련 내용을 찾아 보여줍니다. 답변 옆의 번호를 누르면 그 문장의 근거와 공식 원문 링크를 확인할 수 있습니다.

예를 들어 “퇴사했는데 임금을 받지 못했습니다. 관련 규정을 찾고 싶어요”라고 질문하고, 검색된 조문과 조건을 읽는 용도입니다. “반드시 얼마를 받을 수 있다”거나 “이 소송에서 이긴다”는 결론을 보장하지 않습니다.

**중요: 인터넷의 모든 법률을 매번 실시간 검색하는 프로그램이 아닙니다.** 운영자가 수집해 검색용 저장소에 넣은 범위에서 찾습니다. 자료가 빠졌거나 오래되었으면 답변도 제한됩니다.

### 할 수 있는 일

- 생활언어로 관련 법령·판례 검색하기
- 답변 문장과 연결된 인용 근거 확인하기
- 조문·판례의 문맥과 날짜, 공식 원문 링크 확인하기
- 같은 대화에서 이어서 질문하기
- 현재 대화 삭제하기

### 맡기면 안 되는 일

- 승소 가능성, 유·무죄, 손해배상액, 개인별 법정 기한을 확정하기
- 특정 날짜의 사건에 적용되는 법률을 자동으로 정확히 판정하기
- 전문가 확인 없이 답변만 믿고 소송·신고·계약을 결정하기
- 가상 시연 자료를 실제 법률 근거로 인용하기

## 2. 처음 사용하는 방법 — 다섯 단계

### ① 화면 열기

설치 담당자가 프로그램을 실행한 컴퓨터에서 브라우저로 `http://127.0.0.1:8000`을 엽니다. 이 주소는 **현재 사용하는 컴퓨터 자신**을 뜻합니다. 휴대전화에서 같은 주소를 입력한다고 PC의 프로그램에 연결되는 것은 아닙니다. 공개 서비스 주소는 아직 제공하지 않습니다.

현재 별도 회원가입·로그인 화면은 없습니다. 그렇다고 공개 운영을 위한 사용자 인증이 갖춰졌다는 뜻은 아닙니다.

### ② 질문 쓰기

‘법률 정보 질문’ 칸에 상황과 찾고 싶은 내용을 적습니다. 첫 화면의 예시 질문 버튼은 질문을 입력칸에 채워 주며, 검색은 별도로 ‘근거 찾기 →’를 눌러야 시작됩니다.

- 질문은 앞뒤 공백을 제외하고 2자 이상, 최대 1,500자입니다.
- 이름, 상세 주소, 연락처, 주민등록번호, 상대방 신상은 넣지 마세요.
- 한 질문에는 한 가지 쟁점을 중심으로 적으면 좋습니다.

**좋은 질문:** “주택 임대차가 끝났는데 보증금을 돌려받지 못했습니다. 관련 규정과 확인할 조건을 찾고 싶어요.”

**피해야 할 질문:** “홍길동의 주민번호는 …이고 주소는 …입니다. 제가 무조건 이기죠?”

### ③ ‘근거 찾기 →’ 누르기

검색 중에는 ‘근거 확인 중…’이 표시됩니다. 외부 검색 저장소나 모델에 연결하는 경우 시간이 걸릴 수 있습니다. 처리 중에는 새 요청을 중복 전송하지 않도록 입력과 버튼이 제한됩니다.

### ④ 답변보다 먼저 근거 확인하기

답변 옆의 `[1]`, `[2]` 같은 번호를 누르면 다음 내용을 볼 수 있습니다.

- **문서 제목·조문 위치:** 어디에서 찾은 자료인지
- **이 문장의 인용 근거:** 답변과 연결된 원문 구절
- **근거 문맥:** 검색된 발췌 구간의 주변 내용 — 문서 전체는 아닐 수 있음
- **시행일 또는 선고일:** 법령과 판례의 날짜 구분
- **수집일:** 시스템이 자료를 가져온 날짜
- **공식 원문 확인 ↗:** 새 탭에서 출처 확인

읽고 나서 ‘닫기’ 또는 Esc 키로 근거 창을 닫습니다. 조건·예외·부칙이 빠지지 않았는지 공식 원문도 읽으세요. 수집일이 최근이라고 최신 법률이나 본인 사건에 대한 적용이 보장되는 것은 아닙니다. 시연 자료의 링크 역시 그 가상 문장을 실제 법률로 증명해 주지는 않습니다.

### ⑤ 이어 묻거나 대화 끝내기

같은 주제라면 “그럼 어떤 조건을 더 확인해야 하나요?”처럼 이어서 질문할 수 있습니다. 최근 대화를 참고하지만 모든 과거 대화를 완벽하게 기억하지는 않습니다. 주제가 달라지면 새 상황을 분명히 적거나 ‘대화 삭제’ 후 시작하세요.

한 대화는 최대 30회 질문할 수 있습니다. 한도에 도달하면 ‘대화 삭제’를 누르고 새 질문을 보냅니다. 별도의 ‘새 대화’ 버튼은 없습니다.

## 3. 화면의 표시를 어떻게 해석하나요?

- **‘가상 시연 자료 · 실제 법적 근거 아님’**: 화면과 흐름을 시험하는 모드입니다. 검색 결과를 법률 판단에 사용하면 안 됩니다.
- **‘법률 원문 검색’**: 실제 검색 저장소를 사용하는 경로입니다. 이 표시만으로 자료의 완전성·최신성·법적 정확성이 검증된 것은 아닙니다.
- **`extractive`**: 찾은 원문을 발췌해 보여줍니다. AI가 질문에 맞는 결론을 내렸다는 뜻이 아닙니다.
- **`langchain-gpt-reviewed`**: AI가 만든 문장에 대해 인용 및 별도 AI 근거 검토를 거쳤습니다. 사람 전문가의 검토 완료 표시가 아닙니다.
- **`gpt-verified-extract`**: 기존 시연 경로에서 AI가 고른 구절이 원문에 존재하는지 확인한 방식입니다. 실제 검색 경로의 기본 방식은 아닙니다.
- **‘확인 가능한 근거가 부족합니다’**: 현재 자료와 검색 방식에서 충분한 근거를 못 찾았습니다. 관련 법률이 아예 없다는 뜻은 아닙니다.
- **‘검증 실패로 원문 발췌를 제공합니다’**: AI 문장을 그대로 제공하지 않고 검색한 원문으로 전환했습니다. 오류가 해결되었다거나 그 발췌가 법적으로 적합하다는 보장은 아닙니다.

## 4. 내부에서는 어떻게 움직이나요?

### 사용자가 질문했을 때

```text
질문 입력
   ↓
일부 개인정보 형식 가림 + 최근 대화 참고
   ↓
두 가지 방식으로 자료 검색
   ├─ 단어 검색: 법 이름·조문 번호·핵심 표현 찾기
   └─ 의미 검색: 표현이 달라도 뜻이 비슷한 내용 찾기
   ↓
두 검색 결과의 순위를 합쳐 근거 선택
   ↓
원문 발췌 또는 AI 문장 생성·인용 검토
   ↓
답변 + 근거 번호 + 공식 원문 링크 표시
```

‘RAG’는 쉽게 말해 **자료를 먼저 찾고, 그 자료를 바탕으로 답하는 방식**입니다. 찾은 자료가 틀리거나 부족하면 답변도 틀리거나 부족할 수 있습니다.

### 프로그램을 구성하는 부분

- **화면(React):** 질문을 입력하고 답변·근거를 읽는 창입니다.
- **처리 서버(FastAPI):** 질문을 받고 검색과 답변 생성을 연결합니다.
- **단어 검색 저장소(Elasticsearch):** 정확한 단어·조문 표현에 강한 검색을 담당합니다.
- **의미 검색 저장소(Chroma):** 문장의 뜻을 숫자로 표현한 값을 이용해 비슷한 자료를 찾습니다.
- **AI 연결(LangChain/OpenAI):** 질문의 뜻을 검색용으로 표현하거나, 후속 질문을 정리하고 근거 기반 문장을 만듭니다.
- **대화 저장소(SQLite):** 현재 대화와 접근 만료 정보를 관리합니다.

실제 검색 모드에서 검색 서비스가 고장 나면 오류를 알립니다. 가상 시연 자료로 몰래 바꿔 답하지 않습니다.

### 운영자는 자료를 미리 준비합니다

```text
법률 Open API 이용승인
   → 법령·판례 목록과 본문 수집
   → 원문 보관 및 작은 검색 단위로 나누기
   → 두 검색 저장소에 등록
   → 사용자가 질문할 수 있는 상태
```

자료를 자동으로 최신 상태로 유지하는 상시 운영 체계까지 완성된 것은 아닙니다. 운영자의 갱신·검수가 필요합니다. 첨부 PDF/HWP를 내려받는 것과 그 안의 내용을 검색할 수 있게 만드는 것도 다릅니다. 현재 첨부 본문 추출·OCR 검색은 미구현입니다.

## 5. 개인정보·대화 보관·문제 해결

### 대화와 개인정보

- 일부 주민번호·휴대전화번호·이메일 형식은 가립니다. **모든 개인정보를 찾아내는 기능은 아닙니다.** 마스킹 전에 입력 내용이 처리 서버로 전달되므로 처음부터 민감정보를 넣지 마세요.
- 서버에 대화가 저장됩니다. 브라우저에는 대화를 찾기 위한 임시 식별자가 저장되며, 이것은 로그인 계정이 아닙니다.
- 대화는 생성 후 24시간에 접근이 만료됩니다. 물리적 삭제는 이후 세션 생성·조회 등 정리 동작을 수행하는 요청이 들어올 때 이루어지므로 정확히 24시간에 즉시 삭제되는 방식은 아닙니다.
- ‘대화 삭제’는 현재 대화를 서버에서 지우는 기능입니다. 외부 모델 제공자 측 보관이나 별도 운영 백업의 삭제까지 보장하지 않습니다.
- 실제 모드에서는 질문을 OpenAI 임베딩 서비스에 보냅니다. GPT를 켜면 질문·선택된 근거·일부 최근 대화도 전송될 수 있습니다. GPT를 꺼도 의미 검색의 외부 전송까지 꺼지는 것은 아닙니다.

### 자주 생기는 상황

**화면 자체가 열리지 않아요.** 설치 담당자에게 서버 실행 여부를 확인하세요. 로컬 주소는 서버가 실행 중인 컴퓨터에서 사용해야 합니다.

**‘근거 찾기’ 버튼을 누를 수 없어요.** 질문이 2자 이상인지, 이전 요청이 처리 중인지 확인하세요.

**근거가 부족하다고 나와요.** 계약 종류·쟁점·찾고 싶은 규정 등을 더 구체적으로 적어 보세요. 운영자의 데이터 범위에 해당 자료가 있는지도 확인해야 합니다.

**검색 서비스 또는 외부 모델 연결 실패라고 나와요.** 설치 담당자가 ES/Chroma 실행 상태, 색인 등록, 모델 설정과 API 키를 확인해야 합니다. 브라우저에 키를 입력하거나 질문에 붙여 넣지 마세요.

**대화가 만료되었어요.** 이전 대화는 이어갈 수 없습니다. 오류 안내 후 질문을 다시 보내 새 대화를 시작하세요. 한 번의 요청이 만료 오류로 끝났다면 다시 보내야 합니다.

**설치형 앱이나 인터넷 없이도 쓸 수 있나요?** PWA용 기본 파일은 있지만 실제 기기 설치 검증은 남아 있습니다. 법률 검색·AI 답변을 인터넷 없이 제공하는 서비스가 아니며, 답변을 오프라인용으로 저장하지 않습니다.

## 6. 설치 담당자: 키 없이 화면만 시연하기

아래는 **가상 자료로 화면을 체험하는 방법**입니다. 실제 법률 검색이나 연구 성능 검증을 대신하지 않습니다. 일반 이용자는 설치 담당자가 준비한 화면만 사용하면 됩니다.

Python 3.12 이상, Node.js 22 이상을 준비하고 저장소를 내려받습니다. 저장소의 최상위 폴더에서 실행하세요. 아래 명령은 macOS/Linux 셸 기준입니다.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

**실행 전에** 편집기로 `.env`의 다음 세 값을 수정하고 저장합니다. 기존 `.env`가 있으면 덮어쓰지 말고 내용을 확인하세요.

```dotenv
RETRIEVAL_BACKEND=demo
USE_GPT=0
USE_EMBEDDINGS=0
```

그다음 화면을 빌드하고 서버를 켭니다.

```bash
cd frontend
npm install
npm run build
cd ..
uvicorn backend.app:create_app --factory --env-file .env --host 127.0.0.1 --port 8000 --no-access-log
```

브라우저에서 `http://127.0.0.1:8000`을 열고 예시 질문으로 흐름을 확인합니다. 터미널에서 Ctrl+C를 누르면 서버가 종료됩니다. Python·npm 패키지 최초 설치에는 인터넷이 필요합니다.

Windows PowerShell에서는 가상환경 활성화에 `.venv\Scripts\Activate.ps1`, 설정 파일 복사에 `Copy-Item .env.example .env`를 사용하고 나머지 절차를 따릅니다.

## 7. 설치 담당자: 실제 자료로 사용하기

1. 법률 Open API 승인을 받고 인증값 `LAW_OC`를 준비합니다.
2. 승인 범위의 법령·판례를 수집하고, 실제 원문과 수집 범위를 확인합니다.
3. Elasticsearch와 Chroma를 실행합니다.
4. OpenAI 키·과금·외부 전송 정책을 확인한 뒤 자료를 검색 저장소에 등록합니다.
5. 실제 검색 모드로 서버를 실행하고 작은 질문 세트로 근거를 검수합니다.

정확한 명령과 예외 처리는 [법률 데이터 수집·실행 안내](LEGAL_DATA_RUNBOOK.md)를 따르세요. 키는 서버의 `.env`에만 설정하며 GitHub나 브라우저로 전달하지 않습니다. 사용자 질문은 무료라고 가정하면 안 됩니다. 실제 모드의 임베딩·GPT는 운영자의 API 비용을 발생시킬 수 있습니다.

현재 설정은 로컬 연구용입니다. 공개 배포 전에 사용자 인증, 전체 사용량 제한, 개인정보 정책, 법률 전문가 검수 등 별도 준비가 필요합니다.

## 8. 현재 어디까지 확인되었나요?

현재 기록상 오프라인 테스트 36개와 화면 빌드가 통과했고, 실제 검색 저장소 통합 테스트 1개는 실행 환경이 없어 건너뛰었습니다. **승인된 법률 API의 실제 수집, 실제 임베딩·GPT 호출, 법률 답변의 정확도, 실제 기기 PWA는 검증 완료 상태가 아닙니다.** 문서만 추가한 이번 변경에서 해당 기능을 새로 실행한 것은 아닙니다.

연구용 검색 변형은 운영자가 설정·평가하는 기능이며 사용자 화면에 선택 버튼은 없습니다. 새 방법이 기존 방법보다 좋다는 결과도 아직 입증하지 않았습니다.
