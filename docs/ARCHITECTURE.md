# 설계와 한계

## 데이터 흐름

```text
React/PWA -> FastAPI -> 세션 조회/민감 패턴 마스킹
                       -> 후속 질문 규칙 기반 맥락 보강
                       -> BM25 + cosine 검색 -> RRF 상위 3개
                       -> 원문 발췌 / 선택형 GPT 인용 선택
                       -> 문서 ID + 부분 문자열 검증 -> 출처 포함 응답
                       -> SQLite 대화 저장 (24시간 TTL)
```

## 대학생 팀 수준의 결정

기본 실행에는 비용·외부 인프라가 없습니다. Elasticsearch/Chroma/LangChain은 신청서의 최종 목표 기술이지만 초기 MVP에서는 운영 부담을 줄이기 위해 **도입하지 않았습니다**. BM25는 Python으로, 벡터는 SQLite JSON 캐시와 메모리 cosine으로 구현했습니다. 대규모 데이터에 적합하지 않습니다. OpenAI 옵션은 SDK 대신 httpx REST로 작게 구현했습니다.

무료 기본 모드는 문자/단어 기반 cosine이므로 의미 임베딩 검색이나 완전한 semantic RAG라고 부르면 안 됩니다. 임베딩 옵션을 켜야 의미 기반 검색이 실행됩니다. BM25와 두 번째 검색 결과는 RRF(k=60)로 합칩니다. 데모 임계값은 튜닝 전 값이며 정확도 보장이 없습니다.

GPT에 자유로운 법률 해설을 요청하지 않고 원문 구절 선택만 허용합니다. 반환한 구절은 문서 문자열과 정확히 일치해야 합니다. 현재 인용 단위는 문장보다 큰 원문 구절일 수 있습니다. **출처 문자열 검증은 논리적 함의, 완전한 문맥, 법률의 적용 여부, 최신성이나 환각 제거를 보장하지 않습니다.** 답변은 관련 원문이며 개별 사건의 법적 결론이 아닙니다.

후속 질문은 ‘그럼/그러면/그것/이 경우/그 경우/또는/얼마’로 시작할 때 최근 질문 2개를 붙입니다. 일반적인 대화 이해/LLM 질의 재작성은 미구현입니다. 주제가 바뀌면 새 대화를 권장합니다.

## 개인정보·보안

- 인증 계정 대신 추측하기 어려운 256비트 이상 세션 capability 토큰을 사용합니다. 토큰을 아는 사람은 대화를 볼 수 있습니다. 로그인 기반 권한 통제가 아닙니다.
- 브라우저 sessionStorage에는 세션 토큰만 저장합니다. 서버는 마스킹된 질문·답변을 SQLite에 평문 저장합니다. 수동 삭제 API가 있습니다.
- TTL은 세션 생성/조회 시 만료 행을 정리하는 lazy 방식입니다. 정확히 24시간 시점에 물리 삭제되는 것은 아닙니다. 운영 시 주기적 정리·보안 삭제·백업 보관 정책을 추가해야 합니다.
- 질문 길이, 세션당 30회 한도는 데모 가드입니다. 세션 생성 제한이 없으므로 전역 비용/DoS 방어가 아닙니다. 동시 요청에서는 한도 경쟁도 가능합니다.
- React 기본 escaping을 사용하며 임의 HTML을 렌더하지 않습니다. 출처 URL은 공식 도메인의 HTTPS만 허용합니다. 공식 도메인 리다이렉트/실제 문서 진위까지 검증하지는 않습니다.
- GPT 문서/질문은 비신뢰 데이터로 취급합니다. 인젝션 테스트와 전문 검수는 추가로 필요합니다.
- PDF 원본, 추출문, 팀원 연락처, 비밀번호, 실제 API 키는 커밋하지 않습니다.

## 실행 규모와 확장

한 프로세스·소규모 자료·팀 내부 시연이 대상입니다. SQLite 쓰기 경합과 전 문서 cosine 비용이 있으므로 대규모/다중 인스턴스 서비스에 그대로 배포하지 않습니다. 다음 단계는 검색 인터페이스 분리 → Elasticsearch BM25/Chroma 벡터 어댑터 → 한국어 embedding 평가 → 인증/전역 rate limit → 변호사 검수입니다. 개정 법령의 유효기간 필터와 사건 발생일 질의는 반드시 별도로 구현해야 합니다.
