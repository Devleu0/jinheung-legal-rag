# 직접 준비해야 하는 항목과 사용 방법

이 저장소는 API 승인, 결제, 실제 법률자료의 이용권한 취득을 대신하지 않습니다. 아래 절차는 사용자가 수행해야 합니다. PDF에 적힌 비밀번호는 사용하지 않았습니다. 해당 비밀번호는 변경하세요.

## 1. 국가법령정보센터 Open API

1. 국가법령정보 공동활용 사이트 https://open.law.go.kr/ 에서 현재 이용 신청 절차와 개발가이드를 확인합니다.
2. 법령·판례 등 필요한 서비스 범위와 신청자 식별값(OC 등)을 발급/승인받습니다. 정확한 인증 방식과 응답 스키마는 승인받은 서비스의 최신 공식 문서를 따릅니다.
3. 소규모 범위(근로계약, 임대차, 층간소음)부터 목록 검색 → 식별자 확인 → 본문 조회 순서로 수집합니다. 판례는 사건번호·선고일·법원과 본문을 함께 보관합니다.
4. 호출 한도·이용약관·재배포 조건을 확인하고 재시도 간격과 수집 로그를 둡니다. 판례의 비식별 처리를 유지하고 당사자 정보를 복원하지 않습니다.
5. 본문을 조항/항 또는 판례의 의미 단락 단위로 나눕니다. 각 조각은 최대 12,000자, MVP 전체는 5,000개 이하입니다. 토큰 한도에 따라 더 짧게 나누세요. 표·단서·예외·별표를 분리해서 의미를 잃지 않도록 검수합니다.
6. 아래 JSON 배열로 저장합니다. 예시는 **스키마 설명용이며 법적 근거가 아닙니다**. 실제 인덱싱에는 승인받은 원문만 넣으세요.

```json
[
  {
    "id": "law-식별자-조문-시행일",
    "title": "공식 법령명 또는 판례명",
    "kind": "law",
    "locator": "제N조 제N항 또는 사건번호·법원·선고일",
    "text": "승인받은 API 응답의 정확한 원문으로 교체",
    "url": "https://www.law.go.kr/공식원문경로",
    "effective_date": "2026-09-23",
    "retrieved_at": "2026-09-23"
  }
]
```

`kind`는 `law` 또는 `case`, 판례의 `effective_date`는 이 MVP에서 선고일을 담는 공통 날짜 필드입니다. 후속 개발에서 필드를 분리하세요. 날짜는 반드시 실제 값으로 바꾸세요. 과거 사건은 당시 시행 법령이 필요하며 현재 시스템은 시점별 적용 법령을 자동 판단하지 않습니다.

```bash
# 실제 원문 JSON은 runtime/ 아래에 두어 Git에서 제외
python scripts/import_data.py runtime/downloaded.json --output runtime/legal.json
# .env에서 아래 주석을 해제한 뒤 서버 재시작
# LEGAL_DATA_PATH=runtime/legal.json
```

수집기는 API 스키마마를 추측해서 구현하지 않았습니다. **현재 자동 Open API 수집은 미구현**이고 검증된 JSON 가져오기만 구현되어 있습니다. 수집 담당자는 승인 문서 기반 어댑터를 `scripts/`에 추가하고 오류·페이지네이션·중복·개정 이력 테스트를 작성해야 합니다. 형식 검증은 원문 진위·시행일·최신성 확인을 대체하지 않습니다.

## 2. OpenAI 임베딩과 GPT (선택·유료)

1. https://platform.openai.com/ 에서 프로젝트를 만들고 사용 권한이 제한된 API 키를 생성합니다. PDF의 로그인 계정/비밀번호를 API 키로 사용하지 않습니다.
2. 예산/알림을 설정합니다. 제공자 예산 알림만으로 강제 과금 차단을 보장하지 않으므로 사용량을 직접 확인하세요.
3. `.env`에 `OPENAI_API_KEY`를 입력하고 `USE_EMBEDDINGS=1`, `USE_GPT=1`로 바꿉니다. 처음에는 3~10개 검수 문서로 시험합니다.
4. 서버를 재시작합니다. 문서 임베딩은 최초 시작 시 API를 호출하며 SQLite에 모델+본문 해시로 캐시됩니다. 질문 임베딩은 매 요청 호출됩니다. GPT는 관련 문서에서 인용을 선택하고, 서버는 ID와 정확한 부분 문자열을 검증합니다.
5. API 접근권한·모델 가용성을 확인합니다. 기본 모델은 `text-embedding-3-small`, `gpt-4o-mini`이며 `.env`에서 변경할 수 있습니다.

문서와 마스킹된 질문이 OpenAI로 전송됩니다. 마스킹은 전화·주민번호·이메일 일부 형식만 처리하므로 개인정보 입력 금지가 우선입니다. 실서비스 전 동의·보관 정책과 기관 지침을 확인하세요. API 장애 시 GPT는 발췌로 폴백하고 임베딩 장애는 503을 반환합니다. 최초 임베딩 구축 실패는 서버 시작을 중단합니다.

## 3. AI-Hub 자료

https://aihub.or.kr/ 에서 법률 데이터의 이용 조건·신청·다운로드 절차를 확인하세요. 전체 데이터를 무작정 업로드하지 말고 사용권과 개인정보, 정답 품질, 학습/평가 중복을 검토합니다. 현재 저장소에 AI-Hub 데이터나 자동 다운로드 코드는 없습니다.

## 4. 공개 배포·PWA

현재는 `127.0.0.1`에서 팀 내부 시연용입니다. 외부 배포는 수행하지 않았습니다. HTTPS, 사용자 인증, 사용자별 세션 권한, 역방향 프록시 전역 속도 제한, 비용 상한, DB 접근권한/백업 정책을 구현한 뒤 검토하세요. 세션 토큰이 대화 접근 권한이므로 URL·접속 로그에 남기지 않습니다. 명령 예시는 access log를 비활성화합니다.

PWA는 manifest·아이콘·온라인 서비스 워커를 제공합니다. 답변/API를 캐시하지 않습니다. OS별 설치 지원은 실제 기기에서 확인해야 하며 일부 브라우저는 192/512 PNG 아이콘을 추가로 요구할 수 있습니다. 오프라인 법률 상담 기능은 없습니다.
